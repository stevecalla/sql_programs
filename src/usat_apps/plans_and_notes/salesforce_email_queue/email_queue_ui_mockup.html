Reuse from platform

Already in usat_apps

No re-port — inherit the platform's version.
  • Users, roles & login — signed-cookie auth, .env recovery accounts
  • Panel access control (per-panel grants)
  • Ops console — health, routes, pm2, logs, cron, system commands
  • Metrics framework — events table + report + Ask-your-data
  • Config-status Overview, theme, footer clock, header
Port — EQ settings

Email-Queue domain config

Module-specific admin the platform doesn't have.
  • Salesforce env switch (Production / Sandbox)
  • AI models & pricing table (shared by app + Ask)
  • TEST-MODE banner toggle + admin landing
  • Queue access — general default + per-user overrides
  • Operations menu items specific to EQ (verify SF, list queues, view corrections/context)
Port — EQ dashboards

Email-Queue analytics

Charts on the module's own events table.
  • Funnel visits → threads → AI → drafts → acks
  • Verdicts, AI calls by queue / provider / action
  • Cases worked (per email), top actors
  • Corrections + context-file changes
  • AI spend (real vs test) & cost by model
Net: the framework (auth, access, ops, metrics-events, Ask) is platform plumbing we reuse; what ports is the Email-Queue domain layer — a Settings page and a set of dashboards that read the module's salesforce_email_queue_events table. Because those rows are already PII-free (counts/enums + staff user + queue name), the same analytics safely coexist with the chatbot's no-PII boundary.
